# Architecture

The API owns a serialized worker queue and two signing accounts. A signed request transaction and private input are persisted before broadcast. Local runs use SQLite; the hosted pilot uses a dedicated PostgreSQL schema and a database advisory lock so only one process can operate its signers. Completed hosted history is pruned after seven days; unresolved signed requests are retained for recovery. Witness/proof generation runs in a child process with a three-minute deadline so CPU work does not block HTTP. The parent locally verifies and simulates attacks before submitting the successful settlement. The successful transaction receipt and measured gas are persisted with public proof data.

The Circom source is generated from a frozen trained tree. Every numeric input has bit/range constraints; constants and model identity are fixed by the circuit and verifying key. Context fields enter a Poseidon hash output so they are constrained in the statement. The circuit has three outputs and six public inputs, in the exact order documented in the README and Solidity consumer. Keep this order stable or version the deployment.

The EVM adapter compiles the generated Groth16 verifier and the consumer with solc, targeting Shanghai for the bundled chain. Consumer state transitions are None → Pending → Settled or Refunded. Worker credits are separate from job rewards and withdrawn through effects-before-interactions transfers.

The UI polls the same-origin API, presents actual persisted states and uses the production Vite build. Accounts use scrypt password hashes and server-side revocable sessions; job ownership scopes private history to each account. The Sepolia pilot also supports guest sessions and applies account/visitor, network and global sponsorship quotas. Email verification and password-reset delivery are not configured. External mode keeps operator actions behind an operator token. This is a single-operator sponsored service, not a noncustodial wallet app or permissionless marketplace.
